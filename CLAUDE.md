# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Package manager is pnpm (`pnpm-lock.yaml`).

- `pnpm dev` — start dev server (http://localhost:3000)
- `pnpm build` / `pnpm start` — production build / serve
- `pnpm db:generate` / `pnpm db:migrate` / `pnpm db:studio` / `pnpm db:seed` — Drizzle (see Database)
- `pnpm lint` — `eslint .` (flat config in `eslint.config.mjs`; `next lint` no longer exists in Next 16)
- `pnpm typecheck` — `tsc --noEmit`

GitHub Actions (`.github/workflows/ci.yml`) runs typecheck and lint on pushes and PRs to `develop` and `main`.

There is no test suite configured.

## What this is

A coffee loyalty-card app for Reset Coffee (UI text is in Spanish). Customers sign in with Google and see a card of coffees; after `COFFEES_TO_EXCHANGE` (9, in `src/lib/constants.ts`) the next drink is free. Admins (baristas) search customers and add/reset/delete coffees.

Stack: Next.js 16 App Router (Turbopack), React 19, Better Auth (Google), Neon Postgres + Drizzle ORM, Tailwind + shadcn-style components (`components.json`, `src/components/ui`), PostHog analytics, deployed on Vercel (region `gru1`). Path alias `@/*` → `src/*`.

## Architecture

- **Auth & roles** (`src/lib/auth.ts`, `src/lib/auth-session.ts`, `src/lib/auth-guards.ts`, `src/proxy.ts`, route `src/app/api/auth/[...all]`): Better Auth with Google and the `admin` plugin; its tables (`user`, `session`, `account`, `verification`) live in Neon next to the app's (`src/db/auth-schema.ts`).
  - Roles live in `user.role` (`user` | `admin`). `ADMIN_EMAILS` (comma-separated) only seeds the role of a brand-new account (`user.create.before`); to change admins run `update "user" set role = 'admin' where email = ...`, no redeploy. Baristas have no row in `clients`.
  - Session cookie cache (5 min) means pages and the proxy normally skip the DB. `getSession()` (React `cache`d per request) is what pages, the Navbar and API routes use; `isAdmin()` bypasses the cache (`disableCookieCache`) so server actions always see the current role. **Server actions are public POST endpoints: each admin action must call `isAdmin()`.**
  - `src/proxy.ts` (Next 16's renamed middleware) is an optimistic, DB-free check: no session cookie on `/card` or `/admin` redirects to `/`. Real validation lives in the pages: `/` and `/login` send valid sessions to `/card`, `/card` sends admins to `/admin` and a missing session to `/`, `/admin` and `/admin/scan` send non-admins to `/card`.
  - The customer row (`clients`) is created/refreshed once per login in `databaseHooks.session.create.after` via `provisionClient` (`src/clients.ts`), which also fires the `signup`/`login` PostHog events; `/card` re-creates it if it is missing (e.g. an admin deleted the client while their session was still valid).
  - Login and logout are server actions calling `auth.api.signInSocial` / `auth.api.signOut` (no client SDK). Google redirect URI: `<origin>/api/auth/callback/google`.
- **Data access**: Drizzle over `pg` (`src/db/index.ts`, server-only, pooled Neon URL in `DATABASE_URL`). Schema in `src/db/schema.ts` (`clients`, `wallet_registrations`, `card_events`; timestamps are `mode: "string"` so Wallet's `updated_at` / `passesUpdatedSince` round-trip exactly) and `src/db/auth-schema.ts`. `src/clients.ts` has the read queries (`getClients` returns the page rows and the total count in one query, `getClientByEmail`, `getClientById`, `provisionClient`) and `src/actions/coffees.ts` the server actions (`addCoffee`, `removeCoffee`, `resetCoffee`, `deleteCoffee`, ...), which `revalidatePath("/admin")` and return an `ActionResult`. Drizzle throws where supabase-js returned `{ error }`, so actions catch and map to `{ error }` (keep `redirect()` outside try/catch). Coffee changes are optimistic: `update ... where id = ? and coffees = ?`. **Every card change goes through `updateIfCoffees`**, which in one transaction updates `clients` (including `last_change`) and appends a row to `card_events` (type `added` | `removed` | `redeemed` | `restored` | `reset`, `coffees_after`, `source`, `shop`, `admin_id` from `getAdminId()`); a lost race writes neither. `card_events.client_id` is set null when a client is deleted, so past sales still count. Ids from the browser go through `isUuid` before querying. Admin forms submit through `ActionForm` (`src/components/ActionForm.tsx`), which shows `{ error }` as a sonner toast: a plain `<form action>` drops the returned value. There is no RLS and no public API: the database is only reachable from server code with `DATABASE_URL`.
- **Routes**: `src/app/(protected)/card` (customer view; `CardRefresher` re-renders it every 15 s and on tab focus; `WalletSection` adds the Apple Wallet link and the client's QR), `(protected)/admin` (admin table with `filter`/`page` search params, `CLIENTS_PER_PAGE` = 10), `(protected)/admin/scan` (QR scanning by camera or USB/Bluetooth scanner gun), `(protected)/admin/stats` (owner stats for every admin, from `src/lib/stats.ts`: net coffees/redemptions today, 7 and 30 days, coffees per day, by shop and by barista, `shop` search param; days in `BUSINESS_TIMEZONE`; lifetime totals from the `clients` counters because `card_events` only starts with migration `0002`), `login`, `resetqr` (static QR image). The admin page re-checks `session.user.role` server-side in addition to the proxy.
- **Apple Wallet** (`src/lib/wallet/`): `storeCard` pass built with `passkit-generator` (`pass.ts`); the strip with the stamps is rendered per request with `next/og` (`strip.tsx`), icon/logo PNGs live in `src/lib/wallet/assets/` (traced into the bundle via `outputFileTracingIncludes`).
  - The QR carries `RC` + client uuid hex + HMAC (`token.ts`, `[A-Z0-9]` only so scanner guns typing under a Spanish keyboard layout don't mangle it). `/admin/scan` sends it to `addCoffeeByToken`, which shares `applyCoffeeAdded` with the "+1" button. Same code within 5 s is ignored (double reads). A scan on a full card (9) **redeems** the free coffee (`applyRedeem`: back to 0, `rewards_redeemed + 1`) with an undo toast (`undoRedeem`); the table shows a "Canjear" button instead of "+1" and resetting a full card also counts as a redemption. `clients.last_change` (`added` | `removed` | `redeemed` | `restored` | `reset`) lets the pass say "café canjeado" vs "volvió a 0 sellos"; `total_coffees`, `rewards_redeemed`, `last_coffee_at`, `reward_earned_at` feed analytics.
  - **Google Wallet** (`src/lib/wallet/google/`, optional: needs `GOOGLE_WALLET_ISSUER_ID`, `GOOGLE_WALLET_SA_KEY` = service account JSON key base64-encoded, plus `WALLET_SECRET` and a public `WALLET_BASE_URL` because Google downloads the images). `GET /api/wallet/google/save` (session) upserts a loyalty class/object over REST (`api.ts`, `google-auth-library` for the OAuth token), sets `clients.google_wallet_at` and redirects to a skinny-JWT `pay.google.com/gp/v/save/...` link (`save-jwt.ts`, signed with the service account key). Same QR as the Apple pass. Images are public routes: `/api/wallet/google/hero/{0..9}` (stamps, 1032x344, from `strip.tsx`) and `/logo`. Updates: `notifyPassChanged` (`src/lib/wallet/notify.ts`) runs the Apple push and `notifyGooglePass` (PATCH with `notifyPreference: "NOTIFY"`, only for clients with `google_wallet_at`) in `after()`. Class/object ids carry the environment (`<issuer>.reset_club_<env>`, `<issuer>.<env>_<uuid>`) because main and develop share client uuids. Setup: Google Pay & Wallet Console issuer (demo mode: only test accounts can save the pass, title shows "[TEST ONLY]"), Google Cloud project with the Wallet API enabled, service account added as Developer in the console. Test without Android: save the pass from `/card` on desktop with a test account and view it at wallet.google.com, or use an Android Studio emulator with a Google Play image. The button in `WalletButtons.tsx` is a placeholder until Google's official badge is added.
  - Live updates: `GET /api/wallet/pass` (session) downloads the pass; `/api/wallet/v1/[...path]` is Apple's PassKit web service (auth = derived `ApplePass` token, no session). Registrations live in `public.wallet_registrations`; `clients.updated_at` (trigger) drives `passesUpdatedSince`/`Last-Modified`. add/remove/reset call `notifyPassChanged` (`apns.ts`), an empty APNs push over HTTP/2 with the Pass Type ID cert, sent in `after()`.
  - Apple must reach `WALLET_BASE_URL` without login: prod domain, or the stable `develop` branch alias with Preview Vercel Authentication turned off while testing. Localhost can only build/inspect passes.
  - A client deleted and re-provisioned gets a new uuid, so an old pass returns 404/"Cliente no encontrado" and must be re-added.
- **Analytics**: one PostHog project is shared by every environment and is meant to be shared by every café running this app, so every event (server and browser) carries `environment` (`production` | `preview` | `development`, from `NEXT_PUBLIC_APP_ENV` set in `next.config.mjs`) and `business` (the café, `BUSINESS_NAME` → `NEXT_PUBLIC_BUSINESS_NAME`, default `Reset Coffee`); dashboards must filter on `environment = production` and the `business`. PostHog is for product analytics (funnels, retention, Wallet); numbers shown inside the app come from `card_events`, never from PostHog. Browser: `src/app/providers/ph-provider.tsx` (only inits if `NEXT_PUBLIC_POSTHOG_KEY` exists) and `CardView` (`card_viewed` + `identify` by email). Server: `captureServerEvent` in `src/actions/ph-client.ts` (accepts `set`/`setOnce` person properties). It flushes with `after()` (Vercel freezes the function after responding) and talks straight to `https://us.i.posthog.com` (override with `POSTHOG_SERVER_HOST`); never use `NEXT_PUBLIC_POSTHOG_HOST` on the server, it is the browser proxy (`/analytics`) and hangs from Vercel until the 10 s timeout.
  - Events: `signup` (`source`: `login` | `card`; sets `signup_at` once), `login` (`is_new`), `coffee_added` (`source`: `button` | `scan`, `total_coffees`, `cycle`, `is_first_coffee`, `days_since_last_coffee`), `reward_earned`, `reward_redeemed` (`source`: `scan` | `button` | `dialog`, `days_since_earned`), `reward_redeem_undone`, `coffee_removed`, `coffee_reset` (manual reset of a non-full card), `client_deleted`, `wallet_pass_downloaded`, `wallet_pass_installed`, `wallet_pass_removed`. Coffee events carry `shop` and refresh person properties (`coffees`, `total_coffees`, `rewards_redeemed`, `last_coffee_at`, `has_wallet_pass`). Through the `track` helper in `src/actions/coffees.ts`.
  - Shop: the barista picks the shop in `/admin` (`ShopSelector`, cookie `reset_shop` validated against the names in `WALLET_LOCATIONS`; needs 2+ named shops). `currentShop()` in `src/lib/shop.ts` reads it.

## Database (Neon)

Neon project `cafe-demo` (region `aws-sa-east-1`, Postgres 17) with three branches: `main` = production, `develop` = Vercel Preview (branch `develop`), `dev` = local (`pnpm dev` reads `.env.development.local`, gitignored, which holds the `dev` branch URLs). Create more branches from `main` for experiments; nothing local to run (no Docker).

- Schema source of truth: `src/db/schema.ts` + `src/db/auth-schema.ts`. Change them, then `pnpm db:generate` (writes `drizzle/NNNN_*.sql`; use `drizzle-kit generate --custom` for raw SQL like the `updated_at` trigger in `0001`) and `pnpm db:migrate` against each branch with `DATABASE_URL_UNPOOLED` set (direct, non-pooled connection). `pnpm db:studio` browses the data.
- `pnpm db:seed` loads `src/db/seed.sql` (fake customers) into the branch in `.env.development.local`; it refuses to run with `NODE_ENV=production`.
- Keep `check` constraints in sync with app constants (`clients.coffees` between 0 and 9 = `COFFEES_TO_EXCHANGE`).
- Flow: local (`dev` branch), push `develop`, test the Preview, PR `develop` → `main`. Apply migrations to the `main` branch before (or with) merging code that needs them. Vercel builds with pnpm 11 (`packageManager` in `package.json`); `pnpm-workspace.yaml` `allowBuilds` must list every dependency with a build script, or `pnpm install --frozen-lockfile` fails.
- The compute suspends when idle (free plan), so the first request after a quiet period pays the wake-up.

## Environment

`.env.development.local` / `.env.local` (not committed) and Vercel env vars: `DATABASE_URL` (Neon pooled URL for the branch), `DATABASE_URL_UNPOOLED` (direct URL, drizzle-kit and `db:seed`), `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL` (public origin of that environment), `AUTH_GOOGLE_ID`/`AUTH_GOOGLE_SECRET`, PostHog keys, `ADMIN_EMAILS` (seed for first admins), `BUSINESS_NAME` (café name on analytics events; build-time, so redeploy after changing it), `BUSINESS_TIMEZONE` (IANA zone for the day buckets in `/admin/stats`, default `America/Santiago`). Rotating `BETTER_AUTH_SECRET` logs everyone out.

Apple Wallet (optional; without them the Wallet button and QR are hidden): `WALLET_PASS_TYPE_ID`, `WALLET_TEAM_ID`, `WALLET_SIGNER_CERT` / `WALLET_SIGNER_KEY` / `WALLET_WWDR_CERT` (PEM, base64-encoded), `WALLET_SIGNER_KEY_PASSPHRASE`, `WALLET_SECRET` (HMAC for QR and pass auth; changing it invalidates every issued pass), `WALLET_BASE_URL` (public origin Apple calls back; unset = static passes), `WALLET_LOCATIONS` (JSON `[{"lat":..,"lng":..,"name":".."}]`, up to 10 shops).
